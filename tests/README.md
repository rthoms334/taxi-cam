# Native GPU validation

Run `build.ps1 -Validate` from the repository root with the pinned toolchain. It builds the companion and bridge, runs the native graphics checks on hardware and WARP, and runs the state, lifecycle, telemetry, startup and update tests. `-WarpOnly` explicitly skips hardware checks for hosted CI. Run `smoke-test.ps1` afterward to verify the exact executable and DLL covered by the build receipt. Pull requests to `main` run that same Warp-only validate and exact-binary smoke pair and retain the EXE, DLL and hashes as a PR test-build artifact; they do not publish a release.

`tests/graphics/graphics_validation.cpp` exercises the native bridge. `tests/graphics/compositor_main.cpp` independently checks the compositor across input formats and exposure values. Shared GPU fixtures and pixel oracles live in `tests/support/`. The checks cover camera composition and lower-display preservation, native graphics state replay, pre-existing graphics objects, late-attach learn-on-use of display textures created before hook install, predicate guards and D3D11On12 coexistence. Readback is confined to validation. The optional D3D12 debug layer is used when available; a passing run without it does not establish debug-layer coverage.

The native validation run includes `tests/app/camera_hotkeys_test.cpp`: Ctrl + Shift + L / R / B defaults, saved combinations, editor reset and conflict handling, hidden-window dispatch, controller-button capture, saving and dispatch, and synchronization with supported aircraft TAXI controls. `tests/app/camera_buttons_test.cpp` covers saved controller buttons, press detection across split HID reports, the bounce window and Raw Input registration; neither test reads a physical controller. Profile checks cover the iniBuilds A380's manual-only controls, the PMDG 777 shared `DUS` navigation display with a split tail and no alignment markers, its lower DU on `EICASCDU`, and separate saved calibration. `tests/camera/pmdg_display_select_test.cpp` replays the recorded 777-300ER Display Select Panel sequence (selector lamps and CAM pushes) and checks page replacement, knobs, power loss, the lamp test and invalid values; it does not operate a live aircraft. These fixtures do not operate a live aircraft's buttons.

Marking-colour checks cover profile defaults and independent saved RGB values, missing colour keys, hidden UI preview and picker-result handling, and protocol rejection of invalid RGB and the previous settings layout. Hardware/WARP fixtures verify A350 square corners, recolouring every guide pixel while preserving non-guide pixels, and live updates using retained camera sources. They do not establish appearance in MSFS.

Compositor alpha is an encoding flag: 255 for camera pixels, 0 for overlays. `tests/graphics/stamp_encoding_validation.cpp` runs the production PFD stamp on RGBA and BGRA UNORM and sRGB views of typeless targets. Every camera code must be stored unchanged (within one code on sRGB, 0 and 255 exact), and every overlay code must be stored unchanged on UNORM views and sRGB-encoded (within one code) on sRGB views. A PMDG 777 case in `tests/graphics/scene_frame_output_test.cpp` checks the flags on the camera panes, the `#1C1B22` T and black frames in the production output, then every uniform-region pixel of all four typed patch formats. Neither check establishes appearance in MSFS.

`tests/app/startup_state_test.cpp` checks first-launch Settings visibility, later tray starts, explicit manual opens, failed state writes and preview isolation using a private fixture directory. `tests/app/changelog_test.cpp` checks the What's new parser: schema, bounds, escapes and UTF-8, descending versions, hiding notes above the installed version, dialog text, and the per-version read marker in an isolated `settings.ini`. It also validates the repository's `changelog.json`. It does not fetch from GitHub; the download and dialog need a manual check. `tests/app/connection_recoverability_test.cpp` checks the Auto-connect preference, Connect/Disconnect command queue, setup request serial and attach gating. The companion-control checks cover rapid reconnects, owner changes, heartbeat expiry and mutex contention; hidden UI/IPC checks verify immediate Disconnect publication and calibration preservation. `tests/app/camera_status_test.cpp` verifies distinct status reporting for stopped cameras, pending recovery and successfully recovered cameras.

`tests/app/rotating_log_test.cpp` checks bounded current/previous text logs, continued logging after rotation, oversized legacy history, write/rotation failures and concurrent process writers in isolated directories. Multi-record batches cover all-or-nothing validation, record order, mid-batch rotation and legacy recovery matching single appends, a write failure that stops the batch without part of its record, a held log lock that drops the batch without blocking, the bounded record buffer, and batch contiguity under concurrent writers. `tests/graphics/crash_evidence_test.cpp` checks bounded renderer-fault retention separately from the unchanged one-shot exception capture contract. These tests never rotate or delete user logs.

`tests/app/settings_store_test.cpp` checks per-aircraft profile files in isolated fixtures: the shipped camera rate and parked floor and their one-shot markers, dynamic tail, that keys of retired settings (camera weather, Match main view lighting, exposure, automatic exposure and night boost) are ignored on every aircraft and dropped by the next save, that an invalid profile is rejected without rewriting it or changing the caller, and legacy import. `tests/app/notification_settings_test.cpp` checks that `[messages] notifications` defaults on, that a `settings.ini` written by protocol 10 with only `in_simulator` keeps the user's choice, and that a save writes the new key and removes the old one. `tests/app/sim_messages_test.cpp` covers the event texts, the per-event toast table (`toast_policy`: only simulator unsupported, presentation stalled, camera startup failed and hook storm toast; routine events are refused before the limiter and do not spend its budget), edge detection, the repeat limiter and the bridge-to-companion notification log (order, no replay, freshness, ring wrap); whether a toast appears while MSFS is full-screen is a live check.

`tests/camera/manager_inspection_test.cpp` checks every manager-chain read and reread, field changes and identity refusals. `tests/camera/scene_recovery_test.cpp` covers temporary pair and manager failures followed by guarded cleanup and bounded retry, startup calibration after an early inspection failure, and fatal identity refusal across later failures. Arrival recalibration after a long sector retains the closed pair (no erase or replacement create) until the latch completes (issue 84), and `tests/camera/source_view_test.cpp` checks that the calibration pool scan never reads or selects the retained pair's own views. These checks do not establish the cause of an individual simulator memory-read failure, or that the replacement-pair renderer crash is avoided in MSFS.

`tests/camera/local_memory_test.cpp` checks exact reads, access guards, bounded metadata caching and fresh endpoint validation. Large-allocation fixtures verify that overlapping suffix observations reuse a fresh endpoint query while retaining every original metadata comparison, independent queries for separate regions, rejection of conflicting observations and the original cache capacity. Query-count assertions are deterministic; diagnostic timings do not establish simulator FPS gains.

`tests/camera/private_page_memory_test.cpp` checks the private-page mode: allocation identity, actual page protections, exact rereads and budgets, cross-page fields, cold and trimmed pages proven after their exact read without region scans, direct copies that fail cleanly when a proven page is decommitted (also under a racing decommit thread), batched page proofs whose unread pages are never endpoint-checked, mapped/COW/image refusal, changed or released memory, nested/thread-local scopes, and capacity fallback retaining earlier proofs. It explicitly distinguishes requested-page protection changes from unrelated unread-page changes. The original full-region and image-reader tests remain in the suite.

`tests/camera/image_page_memory_test.cpp` checks explicit image-page mode using isolated data pages in its own executable: exact main-module identity, bounds, COW image pages, guard/no-access/execute-only refusal, exact reads, both private/image cache-type rejection directions, endpoint changes, capacity fallback and nested/thread-local isolation. Default image readers and full-region scopes retain their original semantics. `tests/camera/writable_span_memory_test.cpp` checks the fresh AA flag-span validator, including cross-page and cross-allocation bounds, exact current `PAGE_READWRITE` protection, protection changes and all-or-nothing flag-read output. Both suites exercise unavailable-API and nonresident-page fallbacks through `TAXI_LOCAL_MEMORY_TESTING`; those fault controls are compiled out of production builds. The existing AA tests retain flag, override and closed-gate behavior checks.

The dynamic compatibility checks cover relocated instruction templates, cross-references, PE metadata and static RTTI identity with synthetic images. `tests/camera/camera_contract_test.cpp` exercises the complete generated model and rejection of incomplete or ambiguous evidence. These tests do not establish compatibility with an unobserved simulator build.

`tests/camera/retained_profile_test.cpp` covers empty startup cancellation, pending native operations and preservation of complete or partial owned pairs. `tests/camera/runtime_test.cpp` exercises the production request API on a wrong-host executable, including a queued empty stop followed by an aircraft-session transition. Mixed DLSS render/display sizes retain independent bounds in `tests/camera/view_resize_test.cpp`. `tests/camera/view_output_test.cpp` checks the output admission predicate used before any render gate opens (mode 2, present resource, view and Bitmap at the requested pane, and the diffuse texture's render-target record; each missing element refuses alone) and the bounded closed-gate wait for a new pair's pane output. `tests/camera/owned_view_test.cpp` covers the render-target record resolution (`[T+0x48]?[+8]?[0]`, else `[T+0x40]`) for the diffuse, add-diffuse and depth-stencil slots, including the retained fault state of a pane-sized Bitmap whose texture has no record. `tests/graphics/crash_evidence_test.cpp` covers the version-2 record's bounded fault-time copies and legacy 4 KiB record retention. These tests do not reproduce the renderer; the aircraft-swap CTD acceptance test remains the identical simulator reproduction.

`tests/camera/body_pose_provider_test.cpp` includes a worker deliberately blocked independently of its stop event. Repeated stop, initialization and profile-selection requests must return promptly, preserve the exact worker/handles/profile, and permit cleanup and a profile change only after that worker exits. It does not require or manipulate a running simulator.

Flight-reset cases cover load/teleport begin and completion, intermediate Sim events, loaded-flight Connect readiness, invalid WORLD data before a public epoch change, and fresh identity/body/WORLD requirements independent of the currently selected adapter. `tests/camera/scene_session_reset_test.cpp` exercises the production pair controller with unpublished creation, partial or refused retirement, stale empty snapshots and fresh restart. These synthetic packets do not establish actual simulator flow-event delivery.

The end-flight/reload regression supplies valid telemetry after FLT_LOADED and still requires FLIGHT_START before readiness, calibration or TAXI commands resume. It checks both event orders, Sim-stop before FLOW_END, and preservation of the subscribed worker during same-profile setup. Native admission checks reject a different flight epoch while permitting epoch zero for first Connect in an already loaded flight; old ownership can still retire. These tests do not establish that the reproduced renderer CTD is resolved.

`tests/camera/lifecycle_timing_test.cpp` checks the lifecycle sub-timers behind the `Lifecycle event` log line: per-kind sums, call counts and slowest call, a backward clock step ignored, `proofs` as a lifecycle section less the native calls inside it (never negative) and the per-update reset. It checks the 16-entry event ring (oldest events kept in order, drops counted when full, wraparound), 200,000 events pushed by one thread while another takes them (none torn or out of order, and taken plus dropped equal to pushed), and the line's format and truncation.

`tests/camera/render_schedule_test.cpp` covers 5–60 activation budgets, simulator cadence limits, uneven update intervals, live rate/feed changes, mandatory closing intervals and the idle update after each close (three feeds at 24 fps change a gate on at most two updates in three). Settings, IPC, saved calibration and hidden UI checks include 5, 10 and 15. The shipped unset default is 10. Setup writes `camera_rate=10` once for this version into existing settings and known profile INIs and stamps `camera_rate_revision=2`; a prior force-5 stamp (`camera_rate_revision=1`) is migrated once. Later installs keep a user-changed rate. Companion load still keeps a later user-saved rate. Existing scene-demand tests retain bounded startup warmup and repeated OFF/ON ownership checks.

`tests/graphics/metadata_batch_bridge_test.cpp` exercises production lookup caching, idle forwarding, fresh PFD recording requirements, lifetime/address reuse and descriptor discovery. Its isolated CPU timing comparison does not establish simulator FPS. It also drives a state hook through cached hits, a recording change made on another thread, a retired list at the same address, an expired registration and a contended recording. `tests/graphics/source_observation_test.cpp` checks combined draw tracking and idle capture suppression while retaining source-state evidence, recorded consumers and source leases. Frame-output and queue-tail tests cover optional GPU timestamps, completion-fence readback, unsubmitted discard and disabling diagnostics with a measurement pending.

`tests/graphics/scene_runtime_contention_test.cpp` holds a real application submission transaction while another thread services completed camera inputs. Service must return without failing output or releasing the pending input leases; after the application transaction finishes, composition must resume with the new pixels. Queue-tail tests separately cover helper refusal under the manager mutex, unrelated cross-queue bypass, and retained serialization for owned GPU reads/writes. `tests/graphics/scene_queue_tail_test.cpp` also draws three published feeds in one list and requires one receipt to capture all three, run their tails in one `ExecuteCommandLists` call after the application's, and leave each snapshot equal to its own feed's last draw. It replays a recording at set times since the last capture to check the capture spacing at rates 1, 2, 5 and 10, and checks that a receipt queues a `Wait` only when its queue changes and that receipts without source work still Signal, are counted and, when the device fails mid-receipt, quarantine their packets. Its CPU-only `--submission-locks` run also repeats one Reset scenario with and without the slot each Reset returned and requires the lock-free clean Reset to leave the same state as the locked one at every step, with its lock-free, locked and expired Resets counted. `ordered_waits_name_their_lock` holds `mutex_`, then `submission_mutex_`, and requires an ordered batch behind each to escape within its budget and count one expired `wait1000` wait against that lock, not the other.

Session-reset GPU cases block the actual producer queue, reset the session, replay old work and verify source resources survive until fence completion. Old frames cannot publish afterward. Camera and calibration snapshots stay disabled until the exact new session generation resumes; old command lists require a new native Reset. The metadata bridge fixture separately rejects closed display proofs from earlier sessions while retaining live resource identity for rediscovery.

`tests/graphics/late_attach_test.cpp` checks profile-switch eligibility, complete distinct display associations, bounded binding-hint reuse, retirement, stale incarnations, ambiguity and RT-exit refusal. Reconnect checks reset routes, activity and recovered bindings, preserve native identities, and keep the new discovery window open despite known descriptor aliases. Repeated ini A380 discovery polls must preserve explicit single-side calibration choices, including an ID that was previously selected automatically; genuinely automatic stale targets still recover to the complete allocation group. The ini A380 graphics fixture creates all eight typeless displays and their UNORM/sRGB application views before hook installation, observes some under the initial FBW profile, then verifies automatic selection, camera pixels and calibration after applying the ini profile. Recovered application-view formats remain unknown; owned typed output is tested separately from native descriptor evidence. Learn-on-use cases check the seen set's capacity, full probe runs and forgetting, that registered resources skip classification, that placed-footprint copies classify only their texture side, and that a creation missing the registry lock forgets its address. These checks do not establish live simulator discovery order or final presentation.

The PFD detector and bridge metadata tests also replay A350 activity captured after powering up from cold and dark. They cover waiting through unpowered/static candidates, admitting the newly active displays, automatic adoption of the working pair, and retention of its sides. The detector keeps ambiguity, sampling, counter and identity checks; the captured replay is distinct from testing the revised binary in MSFS.

A second A350 replay covers opaque views with zero native draw counts: three five-mip auxiliary textures lead submission counts, while the two EFIS candidates lead the separate three-member one-mip typeless group. Detector and actual bridge routing tests cover partial boot, complete-group confirmation, full reset and manual selection preservation. Left ID47 was user-confirmed; inferred right ID45 and the revised binary still require live verification. A359 coverage of this second stream is a fixture extension of the observed A35K session.

`tests/graphics/pfd_split_submission_test.cpp` reproduces opaque views created before Connect with separate entry, producer, exit and consumer lists, and with leading exits followed by consumers inside the same original list. Thirty-six hardware/WARP cases cover ini A380's eight typeless displays, FBW's two/three five-mip candidates, explicit SRV/COMMON exits, and insertion before the first original list after a previously submitted producer. Pixels copied by the original consumer must contain calibration or actual camera output; replay and subsequent native overwrite preserve order. Lower trim and unselected displays remain unchanged. A live ini A380 snapshot showed a complete exit list also containing GPU work, which the previous barrier-only submission path rejected. Subsequent user testing confirmed rendering, while boot-time automatic assignment selected incorrect instruments on both A380 integrations.

`pfd_submission_proof_test.cpp` rejects incomplete recordings, stale identities, aliases, split barriers and suspended/resuming passes. `pfd_submission_pool_test.cpp` checks later SRV sampling, untouched lower mips, bounded packet exhaustion, covering-fence leases and permanent quarantine. Its readback case copies a display region into a READBACK buffer, rejects non-READBACK buffers and malformed completion counters, and checks that the completion serial rises only after the covering fence, never falls for an older request and is not raised by a cancelled packet. `pfd_split_submission_test.cpp` requests a snapshot of an unrouted pre-hook display with no camera or calibration patch ready and compares the image with the native gradient. `tests/app/display_snapshot_test.cpp` covers the size fit, box filter, RGBA/BGRA order, row padding, bottom-up BMP encoding and the replace-through-temporary save. None of these show what a live cockpit texture looks like. `queue_patch_snapshot_test.cpp` tests camera/calibration geometry, nonblocking snapshots, pending-GPU ordering and stable buffers. The queue observer's `augment` mode verifies one native call and unchanged original order, including malformed, contended and reentrant refusal. No new thread suspension or D3D11On12 bootstrap is used. The separate D3D11On12 Game Capture coexistence fixture remains part of native validation.

The mixed/first-list cases also issue an actual timestamp query and buffer copy before the display exits. They verify the buffer result as well as display pixels, so harmless earlier GPU work cannot silently disable prefix delivery. Proof tests distinguish state-disjoint work from render-target writes while keeping every GPU operation ineligible for the barrier-only tail path.

The on-demand [performance sampler](../tools/performance/README.md) has separate isolated checks and does not become part of the installed runtime. Live simulator measurements remain a separate acceptance step.

Additional focused checks remain available:

- `tests/hooks/render_boundary_test.ps1`: native render-boundary observations.
- `tests/installer/package_test.ps1`: exact five-file runtime inventory, validated binary hashes, and verbatim `LICENSE.txt` and `THIRD_PARTY_NOTICES.txt` contents.
- `tests/setup/startup_xml_test.cpp`: strict launch parsing, opt-in repair of the recognized mislabeled launch header, exact-original backups, add-on/comment preservation, idempotence, concurrency/encryption refusal with injected backup, protection and visibility faults, and physical-path visibility checks before XML writes.
- `tests/setup/prerequisites_test.cpp`: missing, 32-bit, truncated and malformed PE fixtures for Windows and simulator components, and app-local runtime precedence. No fixture is loaded or executed.
- `tests/installer/setup_commands_test.ps1 -SetupHost <setup-host-test.exe>`: the companion's installer commands in private LOCALAPPDATA/APPDATA fixtures with a fixture process list: running MSFS/companion refusal, prerequisites, packaged-path visibility, startup configuration, Steam-header repair, simulator-specific XML inheritance, ambiguous-discovery fallback, legacy add-on retention, settings reset/removal, uninstall rollback across several owned startup files, and junction refusal.
- `tests/app/camera_rate_migration_test.cpp`: the companion's one-shot `camera_rate=10` profile migration, its shared stamp with earlier Setup versions, revision-1 restamp, later user edits, a missing `settings.ini`, failed-write retry, junction refusal and preview isolation.
- `tests/installer/wizard_startup_selection_test.ps1`: compiled wizard argument fixtures for inherited versus explicit/edited XML choices, silent simulator overrides and the final installation guard. The recorder refuses before installation and leaves fixture XML files unchanged.
- `tests/installer/test-installer.ps1 -Installer <setup-path>`: checks the compiled installer and matching receipt through installation, update and uninstall fixtures, including automatic-startup retry on a later Setup attempt, safe manual fallback, a running simulator, calibration import and preservation, and legal notices. The isolated fixture installs the setup command test host as its companion, so its process checks read a fixture process list. Successful installation scenarios use an isolated test identity and fixture directories; they do not verify MSFS auto-launch.
- `tests/diagnostics/test.ps1`: interface-inventory fixtures, real LLVM decoding and wrong-process refusal. See [diagnostic tools](../tools/diagnostics/README.md).

These checks do not establish live simulator compatibility, texture targeting, camera placement, lighting, motion or performance. Simulator observations must be recorded separately from local GPU and UI results.
