# Keyboard shortcuts and controller buttons

In **Settings → Setup → Taxi cameras**, the **Turn them on with** card has a row for each taxi camera action, with three columns: **Keyboard · all aircraft** (the shortcut), **Controller · all aircraft** (a [controller button](#controller-buttons)) and **Cockpit L:var · this aircraft** (a [cockpit L:var](#cockpit-lvars)). The door camera's row is on **Setup → Door camera**, under **Turn it on with**. A status line appears below a control only when something needs attention, such as an unsaved change or a shortcut Windows refused; it is hidden on **Taxi cameras** while **Advanced** is on. The shortcuts work while MSFS has focus and Taxi Cam is hidden to the tray. Taxi Cam must remain running.

| Action | Default shortcut | Behaviour |
| --- | --- | --- |
| Left camera | Ctrl + Shift + L | Toggle the left display |
| Right camera | Ctrl + Shift + R | Toggle the right display |
| Both cameras | Ctrl + Shift + B | Turn both on; if both are already on, turn both off. The lower display is not changed |
| Lower camera | Ctrl + Shift + D | Toggle the lower display on aircraft that have one (the lower ECAM on the Aerosoft A340-600 and iniBuilds A340-300); other aircraft report that there is no lower display camera |
| Door camera | Ctrl + Shift + V | Toggle the [door camera](aircraft-profiles.md#door-camera) on its display; until a display is chosen it reports that |

Each display contains the nose and tail views; the door camera fills its own display. Holding a shortcut does not repeatedly toggle the display. Each action can also have a [controller button](#controller-buttons).

Click a shortcut field and press the combination you want, then select **Next**, which saves the shortcuts and controller buttons for all aircraft with the rest of the step. Use Ctrl or Alt with a letter, number or function key; F12 and reserved system combinations are unavailable. **×** beside the shortcut disables it. **Reset shortcuts** (on **Taxi cameras**) restores Ctrl + Shift + L / R / B / D / V. It takes effect when saved. Shortcuts must be different for each action. Unsaved shortcut and button changes are kept while you move between the Setup steps, and discarded when you leave **Setup**.

A shortcut Windows did not accept says so below it. If another app has registered the same combination, choose a different one or close that app and select **Next** to retry. A conflicting shortcut does not prevent the other shortcuts from working.

Shortcuts preserve **Overview → TAXI buttons**, whether it is on or off, and end target calibration. On FBW A380 and iniBuilds A350, they update the aircraft's corresponding TAXI button state: turning a display off by shortcut also turns its cockpit button off. With **TAXI buttons** enabled, subsequent cockpit clicks continue to control the displays. With it disabled, the camera preview is controlled manually and shortcuts still synchronize their selected aircraft buttons. The iniBuilds A380's INOP buttons are not used; its cameras use manual keyboard requests or the camera switches under **Overview → Cockpit displays**. On the PMDG 777 the cockpit CAM button selects displays. The Left, Right and Both shortcuts add the navigation displays manually on top of that selection, never write to the aircraft, and leave **Overview → CAM button** unchanged. A display turned on by CAM is turned off with CAM. The SD shortcut (initially Ctrl + Shift + D) adds the lower DU the same way. On the Aerosoft A340-600, the shortcuts set the matching CAM CAPT, CAM F/O and CAM SD selector latches. The iniBuilds A340-300 has no camera control, so its Left, Right, Both and SD shortcuts are manual requests only, as on the iniBuilds A380.

Aircraft button control requires current simulator telemetry. A pending toggle waits for acknowledgement before another event can be sent for that side. If the aircraft cannot confirm the change, Taxi Cam reports it rather than repeatedly toggling the button.

Shortcuts do not turn on a disabled camera service. Aircraft identity and flight-session checks still apply. Display requests reset when the flight or selected aircraft changes and when Taxi Cam restarts. Shortcuts preserve unfinished calibration edits in the settings window.

The key combinations apply to all aircraft and are saved separately from calibration in `%LOCALAPPDATA%\Taxi Cam\hotkeys.ini`. Existing saved shortcuts take precedence over new defaults, including the earlier Ctrl + Shift + F9 / F10 / F11 combinations. A file saved before the SD shortcut existed gains Ctrl + Shift + D, or leaves the SD shortcut off if another action already uses that combination; one saved before the door camera gains Ctrl + Shift + V the same way. Shortcuts are registered for all of Windows while Taxi Cam runs, so Ctrl + Shift + V (paste as plain text in many apps) goes to Taxi Cam; clear it or choose another combination if you need it elsewhere. To adopt L / R / B, select **Reset shortcuts** on **Setup → Taxi cameras**, then **Next**. This does not reset camera mounts, guide positions or display settings. The app's UI preview does not register global shortcuts.

## Controller buttons

Each action can also be assigned to a button on a joystick, throttle, button box or gamepad that Windows lists as a game controller. Select the action's controller field, then press and release the controller button; Taxi Cam reminds you that MSFS also receives controller buttons. A switch position that the controller reports as a permanently held button, such as the engine master switches on a WinWing throttle, is never picked up. **×** beside it removes the button, or stops waiting for one. Select **Next** to apply. No buttons are assigned by default, and **Reset shortcuts** does not change them.

A button acts when it is pressed; releasing it does nothing. Buttons already held when Taxi Cam starts listening, or when a controller is connected, are not presses. A switch that stays on (a latching toggle) therefore toggles the display each time it is switched on. Presses of the same button less than a quarter of a second apart count once, so switch bounce cannot turn a display straight back off. A button can drive only one action.

Controller buttons work while MSFS has focus and Taxi Cam is hidden, and behave like the shortcuts above: the same aircraft button synchronization, session and speed rules apply. MSFS also receives every controller button, so choose one that has no assignment in the simulator's controls, or clear its assignment there. Taxi Cam cannot detect a simulator assignment.

A button whose controller is not connected shows **Controller not connected** below it. A binding names the controller by its USB vendor and product ID, so it keeps working after the controller is reconnected on another USB port. Two identical controllers share their bindings. Taxi Cam reads controller input only while at least one button is assigned or its field is waiting for a press.

Controller buttons apply to all aircraft and are saved in `%LOCALAPPDATA%\Taxi Cam\buttons.ini`, which is created when a button is first saved. If the file cannot be read, Taxi Cam disables every controller button and reports it; assign the buttons again to recover. The app's UI preview never acts on controller buttons.

## Cockpit L:vars

An aircraft's own cockpit switch can run a camera action too. On **Setup → Taxi cameras** (the door camera's on **Setup → Door camera**), type the name of the cockpit variable (L:var) in the action's **Cockpit L:var** field, choose its trigger with the button beside it (it steps through **Momentary**, **Latched** and **Equals**) and select **Next**. The `L:` prefix is optional. Names use letters, digits, underscores and dots. An empty field unbinds the action.

| Trigger | Behaviour |
| --- | --- |
| Momentary | Each change from 0 to a value of 0.5 or more (a press) works like the action's shortcut. Releasing the switch does nothing |
| Latched | A change to 0.5 or more turns the action's displays on; a change back below 0.5 turns them off |
| Equals | The whole number in the field beside the button, such as a display's page number, turns the action's displays on; any other value turns them off. Choosing **Equals** fills in what the variable reads at that moment, and the line under the field shows what it reads, so selecting that page shows the number to type |

Lamps that read about 1.003 when lit and button animations that read 100 while pushed count as on. The value Taxi Cam reads is shown below each field. Only changes act: a switch already on when Taxi Cam connects, when the aircraft or flight changes or when its name is changed does nothing until it changes again. A bound action follows the same aircraft, session and speed rules as its shortcut. On the FBW A380 and iniBuilds A350 it also updates the aircraft's TAXI button, as the shortcut does.

Taxi Cam only reads these variables; it never writes to them. They are saved per aircraft in the profile's `[bindings]` section (keys `left`, `right`, `both`, `sd` for the lower camera and `door`, each with a `_trigger` of `momentary`, `latched` or `equals`, and an equals binding's whole-number `_value`), so each aircraft keeps its own. The door camera's binding turns the door camera on and off. The bridge streams them through SimConnect every simulator frame, sending only changed values, so a short push is not missed; the companion acts on them within about a fifth of a second. A name the aircraft does not have reads 0 and never acts.

For example, the Fenix A320's pedestal **VIDEO** button is `S_PED_COCKPIT_DOOR_VIDEO`, momentary, and the overhead **CKPT DOOR VIDEO** button is `S_OH_COCKPIT_DOOR_VIDEO`, latched (from the aircraft's `Cockpit_Behavior.xml`; not yet read live). The Fenix's door camera template binds the pedestal button to the door camera. On the iniBuilds A380 (read live on 2026-11-02), `INI_ECAM_ACTIVE_PAGE` is the system display's page and its ECAM control panel **VIDEO** key selects page 16, so `INI_ECAM_ACTIVE_PAGE` with **Equals** 16 shows the door camera with the VIDEO page; its `INI_ECAM_VIDEO` does not change when VIDEO is pressed. The iniBuilds A340-300 uses the same variable, with its VIDEO page at 15 (read live on 2026-11-02). The Aerosoft A340-600's pedestal ECAM video selector, `AB_VC_PDS_ECAM_VIDEO_SEL_Sw` (OFF / CKPT ENTRY in its behaviour files), has no function: it read 0 in both positions on 2026-11-02, so that aircraft's door camera is turned on with its shortcut, a controller button or **Door** on **Overview**. On the FlyByWire A380X (read live on 2026-11-02), the ECAM control panel's **VIDEO** key selects system display page 15 and deselecting it returns the page to -1, so `A32NX_ECAM_SD_CURRENT_PAGE_INDEX` with **Equals 15** turns the door camera on with that page; the overhead **COCKPIT DOOR VIDEO** button is `A32NX_OVHD_COCKPITDOORVIDEO_TOGGLE` and the door panel's **VIDEO** button `PUSH_DOORPANEL_VIDEO`, both latched (each press of the door panel button flips it between 0 and 1).
