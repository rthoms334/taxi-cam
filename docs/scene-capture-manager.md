# Capture manager integration

`SceneCaptureManager` connects actual copy callbacks or native render-target exit transitions, successful native command-list resets and native queue submission receipts to completed GPU camera frames. Its bounded storage admits four device identities, 4,096 command-list identities, 16 capture packets and 256 MiB of packet allocations in total. One recording owns at most one packet per feed. Captures use actual live graphics API arguments matched by `SceneHandoff`; no raw engine-read pointer becomes a COM object.

Register the native device, all native DIRECT application queues with `callbacks()`, and each native command list with its creation-generation token before recording captures. Forward each original application copy exactly once, then call `record_copy_after_forward` only when the adapter has proved an exact whole compatible texture operation. The method independently verifies the source/destination descriptions, handoff identity, device ownership and packet limits. It supports either a matched source or the original source of a matched whole-copy destination.

The native copy observer uses the five-argument overload with its exact command-list object generation. `record_texture_copy_after_forward` checks both locations are subresource zero, destination offsets are zero, and any source box covers the whole image; buffer footprints, partial images, extra mips/layers/samples and mismatched descriptions are refused. The actual native copy runs first, once; the observer bypasses callbacks for the injected snapshot copy. No application-resource barrier is inserted. Repeated native whole copies overwrite the same unsubmitted recording's retained-source packet. A different source, submitted/in-flight recording, changed ownership or generation refuses rewriting. Per-feed copy diagnostics record matched counts, numeric source dimensions/format/mips and a static refusal reason. When native copy observation is active, omit the redundant public-copy capture attempt.

When the scene is rendered directly, the native boundary observer calls `record_render_target_before_transition` **before** the application's original legacy barrier. The required evidence is a complete non-split transition whose actual `StateBefore` is exactly `RENDER_TARGET`, outside active or suspended render passes, covering the only subresource. A bound RTV or a draw alone is insufficient. The packet temporarily changes the source to `COPY_SOURCE`, copies to its own `COPY_DEST` texture, and restores `RENDER_TARGET`; the observer then forwards the exact original barrier call once. The source must be an ordinary color texture with one mip, layer and sample and no simultaneous-access flag. Repeated exits on the same recording and retained source overwrite its existing snapshot, so the last image wins. Already-submitted recordings, different source/list identities, changed scene/resource generations and stale owners refuse rewriting.

The observer also needs recording-level evidence that the list cannot still begin with a cross-list resuming pass: an actual completed draw outside a pass or a completed ordinary non-suspending pass. A clear alone supplies no such proof. Unknown or local-preservation pass accesses refuse capture for that recording. The manager requires the native callback's object generation, rejects unrelated handles through an atomic hint before locking, and still performs authoritative matching afterward. Per-feed diagnostics retain only matched boundary counts, numeric source dimensions/format/mips and a static refusal string; they do not log per-event or expose object addresses.

`record_render_target_before_enhanced_transition` is a separate enhanced-barrier path. Its native input must establish exact `RENDER_TARGET` layout/access with no split/discard. It emits enhanced `RENDER_TARGET` → `COPY_SOURCE` → `RENDER_TARGET` barriers with `ALL` → `COPY` and `COPY` → `ALL` synchronization. It never injects a legacy source transition into an enhanced layout. The owned destination remains a separate resource in legacy `COPY_DEST`. Microsoft requires interoperation on the **same** resource to pass through `COMMON`; see the [enhanced-barrier interoperation contract](https://microsoft.github.io/DirectX-Specs/d3d/D3D12EnhancedBarriers.html#interop-with-legacy-resourcebarrier). Both paths rely on the native observer's recursion bypass while injecting their own commands.

The native queue before callback pins packet membership. A dedicated submission mutex remains owned by that same CPU thread through the original native call and after/refused callback. The state mutex is released during the original call. Each capture-bearing or stable-output consumer submission waits for the preceding already-queued per-device fence signal, then signals its own point after native submission returns. This also orders submissions on different DIRECT queues without waiting for GPU completion on the CPU. Refusal retires the ordering point where possible and quarantines publication; it does not invent a valid camera frame.

A queue-tail capture copies a published source after the first submission batch that drew it as a render target once that feed's interval has passed. Each recording's draw evidence also counts the draws it stands for, under the same manager lock, so the tail sees how often a batch drew the source. With `set_capture_phase(true)` (development only), a capture due after a batch that drew the source exactly once is held until the next batch that draws it, at most one batch per capture. A hold covers only the drawing batch directly after it: when that batch records no capture (no lease, the interval, no packet), or a wipe, retirement, rearm or a batch that leaves the source outside its render-target model comes in between, the hold is forgotten and the next due drawing batch is not held (counted as `forced` when it drew once, `after_multi` otherwise). After a wipe, that is the first such batch once the source state is known again. A held batch records no private list, packet or lease use and leaves the feed's interval untouched.

Only an actual successful native Reset or command-list destruction retires an old recording. An incarnation mismatch is ignored. In-flight receipts keep its packet reserved even if Reset occurs after native submission but before the post callback. Once every receipt returns and the producer fence completes, `poll_completed_frames` leases the owned snapshots in `COPY_DEST`. A successfully retired, never-submitted recording is recycled without a GPU fence. Replayed recordings remain unpublished until retired.

The private compositor queue must remain **unregistered** for ordinary queue notifications. Register every PFD recording that reads the one stable output with `register_consumer_recording`, including consumer-only lists. `begin_private_submission` and `end_private_submission` bracket actual private submission on the same timeline. Only a successful end queues the returned fence/value; use that value with `finish_consumption` after all input reads restore `COPY_DEST`. For a leased frame on which no work was recorded, `discard_frame` releases the lease through an already-queued timeline point. If a prepared composition never submits, `SceneFrameOutput::discard_prepared` discards its closed recording before its input descriptors can change.

Keep the manager, queue callback contexts and stable output alive for the process lifetime. Device/observation failures quarantine packets and prevent further publication. Never disable queue observation while recorded capture/output references remain executable. The manager cannot correct application submissions that bypass the registered native observer. Native device identity compares canonical `IUnknown` identities returned by the native COM objects; mismatched device ownership is refused.

Run `tests/graphics/scene_capture_manager_test.ps1` for 18 hardware/WARP regression runs: public copy capture, native `CopyResource` and `CopyTextureRegion` capture, direct legacy/enhanced render capture, and actual patched native boundary callbacks for both barrier models after either an outside-pass draw or a completed ordinary render pass. Each run covers two captured feeds, second-queue replay, successful reset during an in-flight CPU receipt, blocked producer completion, stable-output consumer ordering, 1,536 checked pixels and 20 canceled-recording allocation reuses. Render tests overwrite each packet after a later application write and verify the final image, four captures/two rewrites, and preserved application transitions. Enhanced modes execute on available hardware and WARP adapters; unsupported devices are explicitly reported as skipped. Run `tests/graphics/scene_frame_output_test.ps1` for two changed compositions through one persistent consumer recording: 1,171,968 exact pixels, nose/divider/tail boundaries and a stable GPU buffer address per run. Validation receipts state whether D3D12 debug-layer coverage was available. These windowless tests do not inspect or modify MSFS.
